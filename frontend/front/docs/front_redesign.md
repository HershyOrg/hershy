# Hershy 프론트엔드 리디자인 가이드

> **목표**: 바이브 코더가 자신의 트레이딩 전략을 블록으로 시각화하고, 코드 한 줄 없이 전략을 만들고, "돈 벌 수 있겠다"는 느낌을 받는 UI

---

## 1. 핵심 인식 전환

### 현재 문제

지금 노드 에디터는 **개발자용 비주얼 코딩 도구**임. `getData()`, `processData()`, `Branch`, 코드 에디터 블록 등 프로그래밍 개념이 그대로 노출되어 있음. 타겟 유저인 바이브 코더는 코드를 AI한테 시키는 사람들이지, 직접 함수를 조합하는 사람들이 아님.

### 방향

- 블록의 언어를 **프로그래밍 → 트레이딩**으로 전환
- `function`, `variable`, `branch` → "감지", "조건", "매수", "대기" 등
- 블록 안에 코드 에디터 **절대 노출 금지** (고급 모드에서만)
- 유저는 전략을 "만드는" 게 아니라 **"말로 조립"**하는 느낌이어야 함

---

## 2. 블록 설계 원칙

### 블록의 단위 = "상황"

함수나 단계가 아님. 하나의 블록은 하나의 **상황**을 표현함.

> "상장 공지가 떴을 때", "베이시스가 좁아졌을 때", "펀딩비가 마이너스일 때"

각 블록 안에는 딱 두 가지만:
- **이걸 감지하면** (조건/이벤트)
- **이걸 한다** (행동)

### 블록 연결 = 상태 전이

블록 간 화살표의 의미는 "이 상황이 끝나면 다음 상황으로 넘어간다".

- 간단한 전략: 블록 2~3개
- 복잡한 전략: 블록 5~6개
- **블록 수 = 전략 복잡도** → 시각적으로 바로 인지 가능

### 왜 고정 파이프라인이 안 되는가

처음에 `[뭘 보고] → [어떨 때] → [얼마나] → [뭘 한다] → [그 다음에]` 5단계 고정 파이프라인을 검토했으나, 실제 전략을 대입하면 깨짐.

**검증에 사용한 4가지 전략:**

| 전략 | 설명 |
|------|------|
| A. 상장 스나이핑 | 거래소 상장 공지 → 즉시 매수 |
| B. 상장 베이시스 | 상장 공지 후 현선물 갭 좁을 때 진입, 넓어지면 청산 |
| C. 코너링 라이딩 | 온체인 매집 감지 → 베이시스 작을 때 진입, 드라이버 움직이면 청산 |
| D. 익스플로잇 펀딩비 파밍 | 온체인 익스플로잇 감지 → 렌딩 → 음펀딩비 대기 → 현물 매도+선물 롱 → 펀딩비 수익 |

**파이프라인이 깨지는 이유:**

1. **"뭘 한다"가 한 동작이 아님**: D전략은 렌딩 → 대기 → 매도+롱 3단계 시퀀스
2. **"어떨 때"가 단발성이 아님**: B전략은 공지감지(1차) → 베이시스 좁아짐(2차) 순차 조건
3. **데이터 소스 레이어가 다름**: CEX API, 온체인 컨트랙트, 지갑 트래킹 등 완전히 다른 인프라
4. **그래서 "상황" 기반 블록이 필요**: 각 상태 안에 [감지 → 행동]이 있고, 행동 결과가 다음 상태로 넘기는 구조

**전략 D를 상황 블록으로 표현한 예시:**

```
[상태 1: 탐지] 온체인 컨트랙트 감시 → 익스플로잇 리스크 감지
       ↓
[상태 2: 준비] CEX에서 해당 코인 렌딩 → 렌딩 완료 확인
       ↓
[상태 3: 대기] 펀딩비 모니터링 → 음펀딩비 n% 이하 확인
       ↓
[상태 4: 실행] 현물 매도 + 선물 롱
       ↓
[상태 5: 수확] 펀딩비 수익 누적 → 목표 도달 시 전량 청산 → 상태 1로
```

## 3. 화면 구성

### 3-1. 대시보드 (첫 화면)

유저가 처음 보는 화면은 에디터가 아님. **"내 전략 대시보드"**.

전략 카드 목록으로 구성:
- 전략 이름
- 한 줄 요약 (예: "펀딩비 역전 시 숏 진입")
- 미니 수익 곡선 차트
- 블록 수 표시 (복잡도 인지)
- 상태 표시 (실행 중 / 대기 / 정지)

**카드의 미니 수익 곡선이 우상향이면 유저가 클릭함. 이게 전부.**

### 3-2. 전략 에디터 (카드 클릭 시)

**레이아웃: 2단 구성**

```
┌─────────────────────────┬──────────────────┐
│                         │                  │
│   블록 플로우 (좌측)      │  실시간 PnL (우측) │
│   세로 한 줄 흐름         │  백테스트 수익곡선  │
│                         │  핵심 수치 3개     │
│   상황 블록들이           │  - 총수익률        │
│   위→아래로 나열          │  - 최대낙폭        │
│                         │  - 거래 횟수       │
│                         │                  │
└─────────────────────────┴──────────────────┘
```

### 블록 플로우 규칙

- **기본 흐름: 세로 한 줄**. 가로 복잡한 노드 그래프 아님
- 분기가 필요할 때만 가로로 갈라짐
- 모든 블록은 기본 **접힌 상태** → 한 줄 요약만 보임
- 클릭하면 세부 설정 펼쳐짐
- 블록을 다 접으면 위→아래로 읽었을 때 **한국어 문장**이 됨

**접힌 상태 예시 (전략 D):**

```
온체인 익스플로잇 리스크 감지
        ↓
CEX에서 해당 코인 렌딩
        ↓
펀딩비 마이너스 전환 대기
        ↓
현물 매도 + 선물 롱
        ↓
펀딩비 수익 목표 도달 시 청산
```

이걸 스크린샷 찍어서 남한테 공유할 수 있어야 함.

### 블록 색상 체계

색은 단계 번호가 아닌 **역할**로 결정:

| 역할 | 색상 | 설명 |
|------|------|------|
| 감지/감시 | 파란색 | 데이터를 보고 이벤트를 감지하는 블록 |
| 대기 | 회색 | 조건 충족까지 기다리는 블록 |
| 실행 | 초록색 | 매수/매도/렌딩 등 행동하는 블록 |
| 청산/종료 | 주황색 | 포지션을 정리하고 빠지는 블록 |

전략이 달라져도 색의 의미는 동일 → 한번 배우면 어떤 전략이든 색만 훑어도 흐름 파악 가능.

### 블록 내부 UI

**코드 절대 안 보임. 대신:**

- 드롭다운 (거래소, 종목, 주문 타입)
- 숫자 입력 / 슬라이더 (임계값, 수량)
- 자연어 입력 ("바이낸스 상장 공지" → 시스템이 데이터 소스 자동 연결)
- 커스텀 로직이 필요하면 "수식 모드" 토글 → 그때만 코드 입력창 열림

### 블록 연결 가이드

자유 연결이 아닌 **가이드 모드**:

- 블록을 놓으면 "다음에 올 수 있는 블록" 자동 필터링
- 호환 안 되는 블록 연결 시도 시 에러 대신 제안
- 완전한 자유 조합은 "고급 모드"에서만

### 실시간 PnL 패널

- 블록 수정할 때마다 **즉시** 수익 곡선 변화
- 파라미터 바꾸면 곡선이 실시간 업데이트 → 게임 같은 피드백 루프
- 핵심 수치 3개 항상 표시: 총수익률, 최대낙폭(MDD), 거래 횟수
- **이 즉각적 피드백이 유저를 빠지게 만드는 핵심**

### 3-3. 실행 상태 (전략 시작 시)

에디터 화면 그대로 유지. 추가되는 것:

- 현재 활성 블록에 **초록색 테두리 반짝임**
- 블록 옆에 실시간 토스트: "BTC 0.01개 매수 체결"
- 타임라인 피드 (선택적): "14:32 - 조건 감시 중", "14:35 - 진입 실행"
- **"내가 만든 전략이 살아서 움직이는" 느낌이 핵심 경험**

## 4. "언제"(실행 주기) 처리

블록이 아닌 **글로벌 설정**으로 분리.

이유: "매 5초마다"(타이머)와 "가격 급등 시"(이벤트 트리거)는 성격이 다른데 한 블록에 넣으면 혼란. 전략 전체에 적용되는 설정이므로 블록 플로우 밖에 배치.

```
┌──────────────────────────────┐
│ 실행 주기: [5초 ▼]            │  ← 블록 플로우 위에 한 줄
└──────────────────────────────┘
        ┌──────────┐
        │ 블록 1   │
        └──────────┘
             ↓
        ┌──────────┐
        │ 블록 2   │
        └──────────┘
```

## 5. 전략 메타데이터 & 비교

### 자동 생성 가능한 것 (시스템이 채움)
- 블록 수 (복잡도)
- 사용 데이터 소스 종류
- 백테스트 결과 (수익률, MDD, 샤프비율)
- 거래 빈도

### 유저가 입력하는 것
- 전략 이름, 설명, 태그

### 시뮬레이션 리포트
- 모든 전략을 **동일 포맷**으로 백테스트 결과 출력
- 단, 전략 타입에 따라 중점 지표가 다름 → 컨텍스트 제공 필요
  - 고빈도 전략: 승률 90% + 소액 수익 (승률 중점)
  - 추세추종: 승률 30% + 대폭 수익 (기대값 중점)
  - 같은 표에 넣으면 리테일은 무조건 승률 높은 걸 고름 → 오해 방지 필요

## 6. 에러 핸들링

전략 실행 중 문제 상황 대응 UI 필요:

| 상황 | 유저에게 보여줄 것 |
|------|-----------------|
| API 연결 끊김 | "거래소 연결이 잠시 끊겼어요. 자동 재연결 중..." |
| 체결 실패 | "주문이 체결되지 않았어요. 재시도할까요?" |
| 잔고 부족 | "잔고가 부족해요. 투입량을 줄이거나 입금해주세요." |
| 급격한 가격 변동 | "비정상적 변동 감지. 안전을 위해 일시 정지했어요." |

모니터링은 "잘 되고 있을 때" 보여주는 것이고, 에러 핸들링은 "문제가 생겼을 때" 유저가 패닉하지 않게 안내하는 별도 레이어.

## 7. 핵심 요약

> 바이브 코더가 혹하는 건 이것:
> **"내가 코드 못 짜도 프로 트레이더급 전략을 눈으로 만들 수 있다."**

**화면 흐름:**
대시보드(수익 곡선 카드들) → 클릭 → 에디터(좌: 세로 블록 플로우 / 우: 실시간 PnL) → 시작 버튼 → 같은 화면에서 블록이 살아 움직임

**설계 원칙:**
1. 코드가 한 글자도 안 보임 (기본 모드)
2. 블록을 접으면 한국어 문장으로 읽힘
3. 색상은 역할(감지/대기/실행/청산)로 고정
4. 파라미터 변경 → 즉시 수익 곡선 변화 (피드백 루프)
5. 어디에 있든 "돈"이 보임
6. 블록 수 = 복잡도 (시각적 인지)
7. 실행 시 블록이 살아서 움직임

**레고처럼:**
블록 하나는 단순, 조합하면 뭐든 만들 수 있다는 느낌. 쉬워 보이는데 결과물이 프로급이면 빠짐.

유저가 원하는 것:
"자본의 2/3를 DEX의 ETH-USDT 페어에 5:5로 예치하고, 나머지 1/3을 CEX에서 2배 레버리지 증거금으로 활용하여 예치된 ETH 가치만큼 100% 숏 헤징한다. 이를 통해 시장 가격 변동(Delta)을 0으로 만들고, 오직 DEX 거래 수수료와 CEX 펀딩비 수익만을 취하며, 자산 가치 변동이 ±15%를 초과할 시 리밸런싱을 수행한다." 
-> 딸깍
-> 전략생성

실제로 포함되어야 하는 것:
]
1. 자산 배분 및 세팅 (Initial Setup)
총 자본: $10,000 (예시)

운용 자산: ETH-USDT 페어 (변동성이 적당하고 거래량이 많은 페어 권장)

자산 분배: * DEX (유동성 공급): 전체 자본의 66.6% ($6,666) 투입.
* 구성: $3,333 상당의 ETH + $3,333 상당의 USDT.

CEX (헤징): 전체 자본의 33.3% ($3,334) 투입.

용도: ETH 무기한 선물(Perpetual) 숏 포지션 증거금.

2. 구체적인 포지션 실행 규칙 (Execution)
DEX 액션: 유니스왑 V2(또는 V3 전체 구간)에 $3,333 상당의 ETH를 예치하여 LP 토큰을 생성한다.

CEX 액션: 바이낸스/OKX 등에서 $3,333만큼의 ETH 숏 포지션을 잡는다.

레버리지: 2배 설정 (증거금 $3,334로 $6,668 규모의 숏이 가능하나, 안전을 위해 1배수 헤징만 실행).

헤지 비율: DEX에 묶인 ETH의 가치($3,333)와 CEX 숏 포지션의 가치($3,333)를 1:1로 정확히 맞춘다.

3. 운용 및 유지 규칙 (Management)
델타 값 유지: * ETH 가격이 10% 상승하면, DEX 내의 ETH 수량은 줄어들고 가치는 오른다. 이때 CEX의 숏 포지션은 손실이 발생하지만, 전체 자산 가치는 일정하게 유지된다.

ETH 가격이 20% 이상 급등/급락하여 DEX의 자산 구성 비율이 깨지면(비영구적 손실 발생), CEX의 숏 포지션 규모를 다시 현물 ETH 가치와 1:1이 되도록 리밸런싱한다.

수익 실현: * DEX에서 발생하는 Swap Fee와 Farming Reward를 정기적으로 수확한다.

CEX 숏 포지션에서 발생하는 펀딩비(Funding Fee) 수익을 추가로 챙긴다. (통상 상승장에서 숏 포지션은 이자를 받음)

4. 리스크 통제 (Risk Control)
청산가 관리: CEX의 증거금률을 실시간 모니터링하며, ETH 가격이 숏 포지션 증거금 대비 80% 이상 상승할 경우 DEX의 LP를 해지하여 증거금을 보충하거나 포지션을 종료한다.

비영구적 손실(IL): DEX의 ETH 가격이 진입 시점 대비 너무 멀어지면 1:1 헤지 균형이 깨지므로, 가격 변동폭이 ±15%를 벗어날 때 시스템은 모든 포지션을 종료하고 재설정한다.
